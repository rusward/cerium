# Спецификация языка Cerium

Версия 0.6 (MVP).

## 1. Обзор

Cerium — небольшой статически типизированный язык. Программы хранятся в файлах `.ce` и
компилируются `ceriumc` в нативные исполняемые файлы. Компилятор разбирает исходник,
проверяет типы, генерирует C99 и вызывает C-компилятор.

Синтаксис похож на C#, но сокращён и имеет несколько собственных черт:

- функции вводятся словом `func`, а тип результата указывается после `->`;
- значения структур собираются литералами без `new`: `Point { x = 1, y = 2 }`;
- циклы — `while`, C-подобный `for` и бесконечный `loop`;
- фигурные скобки обязательны, простые операторы завершаются точкой с запятой.

## 2. Лексическая структура

- Исходник в UTF-8. Пробелы и переводы строк не значимы; строки не завершают операторы.
- Идентификаторы: `[A-Za-z_][A-Za-z0-9_]*`. Зарезервированные слова:
  `int`, `double`, `bool`, `string`, `void`, `func`, `struct`, `return`, `if`, `else`,
  `while`, `for`, `loop`, `break`, `continue`, `true`, `false`.
- Целочисленные литералы: только десятичные цифры, например `0`, `42`.
- Литералы с плавающей точкой: цифры `.` цифры, например `3.14`, `0.5`.
  Экспоненциальная запись не поддерживается.
- Строковые литералы — в двойных кавычках. Escape-последовательности: `\n`, `\t`, `\r`,
  `\\`, `\"`. Настоящий перевод строки внутри строки — ошибка.
- Комментарии: `//` до конца строки и `/* ... */`. Блочные комментарии не вкладываются.
- Пунктуация и операторы:
  `== != <= >= && || -> + - * / % = < > ! . ( ) { } ; ,`

## 3. Грамматика

```
program     := top_level*
top_level   := struct_decl | func_decl | stmt

struct_decl := 'struct' IDENT '{' field_decl+ '}'
field_decl  := scalar_type IDENT ';'
scalar_type := 'int' | 'double' | 'bool' | 'string'

func_decl   := 'func' IDENT '(' param_list? ')' '->' return_type block
param_list  := param (',' param)*
param       := type IDENT
return_type := type | 'void'
type        := scalar_type | IDENT

stmt        := var_decl | assign_stmt | if_stmt | while_stmt | for_stmt
             | loop_stmt | break_stmt | continue_stmt | return_stmt
             | expr_stmt

var_decl    := type IDENT '=' expr ';'
assign_stmt := lvalue '=' expr ';'
lvalue      := IDENT ('.' IDENT)*

if_stmt     := 'if' '(' expr ')' block ('else' 'if' '(' expr ')' block)* ('else' block)?
while_stmt  := 'while' '(' expr ')' block
for_stmt    := 'for' '(' (var_decl | assign_stmt) expr ';' assign_expr ')' block
loop_stmt   := 'loop' block
break_stmt  := 'break' ';'
continue_stmt := 'continue' ';'
return_stmt := 'return' expr? ';'
block       := '{' stmt* '}'
expr_stmt   := expr ';'

assign_expr := lvalue '=' expr

expr        := logic_or
logic_or    := logic_and ('||' logic_and)*
logic_and   := equality ('&&' equality)*
equality    := comparison (('==' | '!=') comparison)*
comparison  := term (('<' | '<=' | '>' | '>=') term)*
term        := factor (('+' | '-') factor)*
factor      := unary (('*' | '/' | '%') unary)*
unary       := ('-' | '!') unary | postfix
postfix     := primary ('.' IDENT)*
primary     := INT | DOUBLE | STRING | 'true' | 'false'
             | IDENT | call | struct_lit | '(' expr ')'
call        := IDENT '(' (expr (',' expr)*)? ')'
struct_lit  := IDENT '{' (field_init (',' field_init)*)? '}'
field_init  := IDENT '=' expr
```

Приоритет операторов, от низкого к высокому: `||`, `&&`, равенство, сравнение, `+ -`,
`* / %`, унарные операторы, постфиксный доступ к полям.

## 4. Типы

| Тип      | Представление              | Примечания                                      |
|----------|----------------------------|-------------------------------------------------|
| `int`    | знаковый 64-битный         | переполнение заворачивается (доп. код)          |
| `double` | IEEE-754 binary64          | inf/NaN допустимы, деление не проверяется       |
| `bool`   | `true` / `false`           | неявных преобразований из truthiness нет        |
| `string` | неизменяемые байты UTF-8   | конкатенация выделяет память, освобождает ОС    |

Имена структур вводят дополнительные значимые типы. Неявных преобразований нет.
`int + double` — ошибка типов; синтаксиса приведения в MVP нет.

Каждое объявление и присваивание сохраняет объявленный тип. Переменные изменяемы, но их тип
фиксируется при объявлении.

### Структуры

```
struct Point {
    int x;
    int y;
}
```

- объявления структур разрешены только на верхнем уровне;
- поля должны иметь скалярный тип (`int`, `double`, `bool`, `string`); вложенные структуры в
  v0.6 не поддерживаются;
- имена полей уникальны внутри структуры; нужно хотя бы одно поле;
- типы структур можно использовать для переменных, параметров и возвращаемых значений;
- структуры передаются в функции и возвращаются по значению;
- литерал структуры обязан инициализировать каждое поле ровно один раз; порядок полей
  произвольный;
- доступ к полю: `p.x`; присваивание полю: `p.x = 5;`;
- структуры нельзя сравнивать через `==`/`!=` и нельзя передавать в `log`; печатайте поля;
- `Point copy = p;` копирует структуру по значению.

## 5. Функции

```
func add(int a, int b) -> int {
    return a + b;
}

func greet(string name) -> void {
    log("hello,", name);
}
```

- функции объявляются только на верхнем уровне; вложенных функций и перегрузок нет;
- тип результата указывается после `->`; `void` означает отсутствие результата;
- все сигнатуры собираются до проверки тел, поэтому функции можно вызывать до объявления,
  включая взаимную рекурсию;
- тело функции имеет собственную область видимости. Параметры находятся в ней же.
  Переменные верхнего уровня внутри функций не видны;
- `log` встроен и не может быть переопределён как функция;
- вызов, результат которого не нужен, можно использовать как оператор, даже для non-void
  функций.

### Возврат

- `return expr;` возвращает значение; `return;` допустим только в `void`-функции.
- Функция с результатом обязана вернуть значение на всех путях. Проверка консервативная:
  анализируются цепочки `if`/`else`, циклы не считаются гарантированным возвратом. Завершающий
  `return` (или `if`/`else`, где возвращают все ветки) удовлетворяет проверке.
- `return` вне функции — ошибка.

### Рекурсия

Поддерживается естественно:

```
func factorial(int n) -> int {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}
```

## 6. Операторы

### Объявление переменных и присваивание

```
int x = 1;
x = x + 1;
```

Инициализация обязательна. `x = 1;` никогда не объявляет переменную: имя должно уже
существовать. Тип переменной фиксирован.

### Блоки и области видимости

- блоки вводят области видимости; переменная из блока не видна снаружи;
- объявление имени, которое уже есть в текущей или внешней области, — ошибка;
- чтение переменной до объявления — ошибка;
- структуры и функции объявляются только на верхнем уровне; вложенность — ошибка.

### `if` / `else if` / `else`

```
if (score >= 90) {
    log("A");
} else if (score >= 70) {
    log("B");
} else {
    log("C");
}
```

Условие должно иметь тип `bool`; фигурные скобки обязательны даже для одного оператора.

### `while`

```
while (i < 3) {
    i = i + 1;
}
```

### `for`

```
for (int i = 1; i <= 5; i = i + 1) {
    log(i);
}
```

- инициализация — объявление переменной с инициализатором или присваивание;
- условие обязательно и должно иметь тип `bool`;
- обновление — присваивание переменной или полю, например `i = i + 1` или
  `p.x = p.x + 1`;
- переменная из инициализации видна только внутри цикла;
- `break` и `continue` поддерживаются; `continue` всё равно выполняет секцию обновления.

### `loop`

```
int n = 0;
loop {
    n = n + 1;
    if (n == 3) {
        break;
    }
}
```

`loop` — бесконечный цикл; обычно из него выходят через `break`.

### `break` / `continue`

Допустимы только внутри `while`, `for` или `loop`. `break` вне цикла — ошибка, как и
`continue` вне цикла.

### Операторы-выражения

Только вызовы функций можно использовать как самостоятельные операторы; `1 + 2;` — ошибка.

## 7. Встроенные функции

Встроенные функции доступны всегда и не могут быть переопределены через `func`.

| Встроенная функция | Аргументы                   | Результат |
|--------------------|-----------------------------|-----------|
| `log(...)`         | любое число скаляров        | `void`    |
| `input(...)`       | необязательный `string`     | `string`  |
| `inputInt()`       | необязательный `string`     | `int`     |
| `inputDouble()`    | необязательный `string`     | `double`  |
| `inputBool()`      | необязательный `string`     | `bool`    |
| `toString(v)`      | один скаляр                 | `string`  |
| `toInt(t)`         | одна `string`               | `int`     |
| `toDouble(t)`      | одна `string`               | `double`  |
| `toBool(t)`        | одна `string`               | `bool`    |

### `log`

```
log(expr, ...);
```

- вариадическая функция; принимает любое число аргументов скалярных типов;
- аргументы печатаются в stdout через один пробел, затем добавляется `\n`;
- `int` — десятичное число, `double` — `%g`, `bool` — `true`/`false`, `string` — как есть;
- `log()` печатает пустую строку;
- `log` возвращает `void`; результат нельзя использовать в выражении;
- структуры напрямую передавать в `log` нельзя.

### Ввод с консоли

```
string name = input("Name: ");
int age = inputInt("Age: ");
double height = inputDouble();
bool ok = inputBool("Continue? (true/false): ");
```

Все функции ввода принимают ноль или один аргумент — промпт. Промпт должен быть выражением
типа `string`; он пишется в stdout и сразу сбрасывается, без добавления перевода строки.

Каждый вызов читает ровно одну строку из stdin:

- завершающий `\n` удаляется; завершающий `\r` также удаляется (ввод CRLF);
- `input()` сохраняет остаток строки, включая ведущие и хвостовые пробелы;
- пустая строка — допустимое значение `input()` (пустая строка);
- конец ввода (EOF) до первого символа — ошибка рантайма, даже для `input()`;
- типизированные функции обрезают пробелы и табуляцию по краям, затем разбирают весь текст:
  - `inputInt`: необязательный знак и десятичные цифры, значение должно помещаться в 64 бита;
  - `inputDouble`: десятичная форма, которую понимает C `strtod`, включая дроби и экспоненту;
  - `inputBool`: строго `true` или `false`;
- если текст не разбирается, печатается ошибка рантайма и процесс завершается с кодом 1:

```
runtime error: invalid int input: '12abc': file.ce:3
runtime error: unexpected end of input: file.ce:5
```

Строки, возвращённые `input()`, выделяются в куче и не освобождаются до завершения процесса;
буферы типизированных функций освобождаются после разбора.

### Явные преобразования

Неявных преобразований и синтаксиса приведения нет. Используйте встроенные функции явно:

```
string label = "answer: " + toString(42);
int port = toInt("8080");
double ratio = toDouble("0.25");
bool enabled = toBool("true");
```

- `toString(value)` принимает один скаляр (`int`, `double`, `bool`, `string`) и возвращает
  строку. Целые печатаются десятично, `double` использует тот же `%g`, что и `log`, `bool`
  становится `true`/`false`, строка возвращается без изменений. Структуры не принимаются.
- `toInt`, `toDouble`, `toBool` принимают одну `string`, обрезают пробелы и табуляцию и
  разбирают весь оставшийся текст. Форматы совпадают с соответствующими `input*`.
- Неверный текст вызывает ошибку рантайма и завершает процесс с кодом 1:

```
runtime error: invalid int value: '12abc': file.ce:3
runtime error: invalid bool value: 'yes': file.ce:7
```

- Результат `toString` для чисел выделяется в куче и живёт до завершения процесса.

## 8. Операторы

| Оператор        | Типы операндов           | Результат |
|-----------------|--------------------------|-----------|
| `+`             | `int`, `double`, `string`| тот же    |
| `- * /`         | `int`, `double`          | тот же    |
| `%`             | `int`                    | `int`     |
| `< <= > >=`     | `int`, `double`          | `bool`    |
| `== !=`         | любой скалярный тип      | `bool`    |
| `&& \|\|`       | `bool`                   | `bool`    |
| унарный `-`     | `int`, `double`          | тот же    |
| унарный `!`     | `bool`                   | `bool`    |
| `.`             | значение структуры       | поле      |

- Деление `int` и `%` усекают к нулю.
- Деление/остаток `int` на ноль вызывает ошибку рантайма и код 1:
  `runtime error: division by zero: file.ce:LINE`.
- Деление `double` на ноль следует IEEE-754 (`inf` / `nan`, печатается через `%g`).
- Арифметика `int` заворачивается при переполнении; `INT64_MIN / -1` даёт `INT64_MIN`,
  `INT64_MIN % -1` даёт `0`.
- Сравнение строк `==`/`!=` сравнивает содержимое, а не указатели.
- `&&` и `||` вычисляются с коротким замыканием.

## 9. Диагностика

Ошибки компиляции имеют вид:

```
file.ce:3:5: error: cannot assign a value of type 'string' to variable 'n' of type 'int'
    n = "text";
        ^
```

Все ошибки типов в программе выводятся до завершения. Код возврата — `1`.

Сгенерированный C содержит директивы `#line`, поэтому диагностика C-компилятора также
указывает на исходный файл `.ce`.

## 10. CLI компилятора

```
ceriumc build <file.ce> [-o out] [--emit-c PATH] [--keep-c] [--static] [--cc NAME]
ceriumc check <file.ce>
ceriumc emit-c <file.ce> [-o out.c]
ceriumc --version
```

- `build` создаёт исполняемый файл, по умолчанию с именем исходника;
- `--emit-c PATH` дополнительно сохраняет сгенерированный C;
- `--keep-c` оставляет временный C-файл и печатает его путь в stderr;
- `--static` передаёт `-static` C-компилятору; на macOS не поддерживается;
- `--cc` выбирает C-компилятор (по умолчанию определяется автоматически: `clang` на macOS, `gcc` на других платформах; MSVC `cl.exe` не поддерживается).

Коды возврата: `0` — успех, `1` — ошибка компиляции/типов/рантайма, `2` — ошибка
использования CLI, `3` — сбой C-бэкенда.

## 11. Полный пример

```csharp
struct Point {
    int x;
    int y;
}

func distanceSquared(Point a, Point b) -> int {
    int dx = a.x - b.x;
    int dy = a.y - b.y;
    return dx * dx + dy * dy;
}

Point a = Point { x = 1, y = 2 };
Point b = Point { x = 4, y = 6 };

log("distance^2 =", distanceSquared(a, b));

for (int i = 1; i <= 3; i = i + 1) {
    log("step", i);
}
```

## 12. Вне рамок v0.6

Массивы, методы и конструкторы, вложенные структуры, сравнение структур, `for` без секций,
`do while`, `switch`, приведения типов, `++`/`+=`, тернарный оператор, интерполяция строк,
дженерики, модули/импорты, сборка мусора. Конкатенированные строки живут до завершения
процесса.
